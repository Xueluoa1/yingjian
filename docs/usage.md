# 映间 · 局域网影音 0.1.4

电脑或 NAS 运行一份服务，手机、电视连接同一局域网后使用。服务端统一保存片源、设备、收藏和观看进度。界面沿用浅灰背景、白色无描边板块、薄荷绿重点区域与黑色胶囊导航。

## Windows 服务端：解压后启动

1. 解压 `Yingjian-Server-0.1.4-Windows.zip`，保留整个目录。
2. 双击 **Yingjian-Server.exe（映间服务端）**，在“本机服务”点击“启动服务”。当前便携包适用于 x64 Windows，内置 Node.js，无需安装依赖。启动器需要 .NET Framework 4.7.2 或更新版本。
3. 点击“打开管理页”，在这台电脑进入管理。默认地址为 <http://127.0.0.1:8080/?view=server>。
4. 在管理页选择“连接设备”。二维码和链接必须选电脑的局域网地址，例如 `http://192.168.2.20:8080`，手机不能使用 `127.0.0.1`。
5. 关闭启动器窗口会收起到系统托盘，服务继续运行；点击“停止”或“退出启动器”才停止本次启动的服务。电脑休眠或关机后，其他设备不能继续使用服务。

启动器提供端口设置、数据文件夹选择、启动/停止/重启、服务状态、局域网地址复制和日志查看。它只停止自己启动的服务；如果旧启动窗口仍在运行，显示“外部启动的服务”，可直接打开管理页，需要在旧窗口停止旧服务后再交给启动器管理。

这是便携式桌面启动器，未注册为 Windows 系统服务，也未自动设置开机启动。`start-windows.cmd` 在便携包中打开启动器，在源码目录中以控制台模式运行。

首次出现 Windows 防火墙提示时，允许家庭“专用网络”。若设备无法访问，检查双方在同一路由器下、没有连接隔离的访客 Wi-Fi，并确认系统防火墙允许 Node.js 的 TCP 8080 局域网入站。不要配置路由器端口转发。

源码运行：安装 Node.js 22 或更新版本，在项目目录执行 `npm ci`，再执行 `npm start`。

## Windows 播放器：连接已有服务

解压 `Yingjian-Player-0.1.4-Windows.zip`，双击 **映间播放器.html**。填写服务端局域网地址或完整配对链接，在打开的页面输入六位连接码或确认配对，即可观看。上次连接地址保存在本机，之后可直接进入片库。

这是独立的浏览器播放入口，不启动 Node.js 或服务端；运行服务的电脑本身也可以打开它观看。播放器标志是播放三角，服务端启动器图标是服务器。手机和电视继续使用已有的 0.1.2 APK，本次不用重装。

## 手机：扫码或链接连接

安装手机 APK 后，有两种方式：

- **扫码连接**：管理页生成二维码；手机 App 点击扫码，允许相机权限，扫描后确认连接。也可以用手机系统相机扫码，在浏览器中确认。
- **地址和连接码**：在 App 的连接页同时输入服务端地址（例如 `192.168.2.20:8080`）和管理页的六位连接码，点击连接。地址可省略 `http://`。也可粘贴管理页复制的完整配对链接，直接确认连接。

二维码、完整配对链接和六位码属于同一次配对，10 分钟内有效，成功使用一次后失效。每增加一台设备，重新生成一次。设备配对后会记住连接；管理员可以在设备列表中断开设备。浏览器和 App 各自保存登录状态，互不通用。

局域网 HTTP 页面不能可靠地直接调用浏览器相机，因此 App 使用原生扫码；网页端使用系统相机打开二维码或手动连接。

## 安卓电视

安装电视 APK，在同一页输入服务端局域网地址（例如 `192.168.2.20:8080`）和管理页的六位连接码，点击「连接服务端」。连接码使用数字键盘；遥控器可在地址、连接码和按钮之间移动。使用方向键移动焦点、确认键选择、返回键返回。服务地址变更时在 App 菜单重新设置。

当前手机和电视 APK 为 0.1.2，修复安卓 WebView 在续播和切换片源后停在暂停状态的问题。APK 是供本地试用的调试签名版本，适合侧载；未上架应用商店。手机/电视真实硬件上的解码能力、遥控器兼容性和厂商 WebView 版本仍需实机确认。

## NAS / Docker

推荐使用 **`Yingjian-Server-0.1.4-nas1-linux-amd64-Offline.zip`**，适用于运行 Docker 的 x86-64（AMD64）NAS。包中包含已构建的 `yingjian-server:0.1.4-nas1` 镜像、校验摘要、容器验收记录和 Compose。安装时不需要下载 Node.js、npm 依赖或重新构建镜像；播放互联网片源仍需联网。

当前完整 Windows 服务端包也内置该镜像。打开启动器的“NAS 部署”，填写 NAS 的局域网 IPv4、未被占用的访问端口和管理密码，点击“校验并导出离线包”，即可得到带配置的文件夹及 ZIP。导出前会重新检查镜像及验收记录。启动器负责准备部署包，随后需要将它传到家里电脑或 NAS。

首次安装：

1. 将离线包解压到 NAS 的一个固定目录。
2. 在 NAS 的 Docker“镜像”页面导入包内 `image.tar`。
3. 使用启动器导出的包时，`.env` 已填写。使用通用离线包时，将 `.env.example` 复制为 `.env`，填写 NAS 的局域网 IP、访问端口、管理密码以及对应的 `PUBLIC_ORIGIN`。
4. 在 NAS 的 Compose 页面创建项目并使用包内 `docker-compose.yml`，使工作目录指向解压目录，然后启动。镜像固定使用本地版本，无需拉取和构建。

也可以在解压目录执行以下命令，由脚本完成校验、导入和启动：

```sh
sh deploy.sh start
```

部署包使用 Docker Compose v2，绑定填写的局域网 IPv4。访问 `http://NAS的IP:所选端口/?view=server`，用配置的管理密码登录，再配对手机和电视。

已有安装应在原项目中更新，保留原 `.env`、项目名和实际数据卷名称，不另建同名容器。导入镜像后，用离线版 Compose 更新原项目的编排内容，再重新创建容器；只重启旧容器不会应用新镜像。`sh deploy.sh update` 会检查已有容器并沿用原数据卷。`sh deploy.sh status` 检查状态，`sh deploy.sh stop` 停止服务。不要执行 `docker compose down -v`，它会删除数据卷。

该镜像于 2026-11-16 在用户 NAS 的独立测试容器中通过非 root 运行、健康检查、管理登录、静态资源、设备配对和重建后的持久化验收。收到成品后，已在本地核对镜像身份、文件哈希、各镜像层和应用源码一致性。当前电脑没有 Docker 引擎，未在本机重复运行容器；验收也没有替换 NAS 上的原服务。

维护者需要更新镜像时，可在有 Docker 的 Linux AMD64 机器运行 `sh scripts/build-nas-image.sh`，或使用 Windows 镜像制作工具；构建和验收通过后，再用 `scripts/package-nas-offline.ps1 -VerifiedBundle <完整目录>` 打包。源码中的 `deployment/nas-offline` 仅保存模板，不包含大体积镜像。`Yingjian-Server-0.1.4-NAS.zip` 是保留的旧源码部署包，需要联网构建；新安装请使用名称带 `Offline` 的成品包。

## 片源与播放

首页按电影、剧集、动漫、综艺、短剧浏览；手机和电视共用年份、地区、类型筛选，并可选择「最近更新」或「评分最高」。筛选选项取自实际返回的数据，没有评分的影片排在评分结果后面。

每个片源的影视独立显示一张卡片，卡片标注实际来源；同名影视在不同片源中会分别显示。点击卡片后使用该卡片对应的片源，影视详情保留剧情、来源、线路和选集，不再提供跨源切换入口。

手机、电视和服务端均可进入「播放设置」，选择浏览全部已启用片源或单个片源，执行延迟测试，以及添加、编辑、启用、停用和删除片源。浏览片源选择与自动下一集设置按设备保存；片源本身的增删和启停对全家生效。延迟表示服务端请求片源接口的耗时，不代表视频码率或播放速度。

播放中的换源入口收纳在播放器的「播放设置」中；按规范片名、年份和分类匹配同一作品，再匹配集数接续进度。不同剪辑版本可能需要微调进度。收藏与观看记录继续按作品保留最近使用的片源。短剧根据片源分类、上级分类或明确类型标签识别，不凭片名猜测。

「最近更新」按每张卡片对应片源的有效更新时间降序排列；兼容更新时间为空/0时的备用字段、秒和毫秒时间戳。卡片显示更新时间，未知时间排后。可点击刷新重新读取片源首批内容。

这些接口没有统一的全库筛选能力，因此服务端按需汇集当前所选、已启用片源的内容，筛选与排序限于已加载范围；点击「加载更多内容」继续读取各源下一页，每个分类/关键词最多读取每源 5 页，缓存 10 分钟。翻页和改变年份、地区、类型不会重复抓取上游。可直接搜索片名查找较旧影片。缺失的年份、地区、类型或评分不会编造，部分来源失败不影响其余影片显示。

界面参考三端预览图加入精选影片、继续观看、家庭片源状态、快捷入口、设备与当前播放、最近动态等实际信息。影片评分只使用片源返回的数据，未接入豆瓣或外部热榜；预览图中的离线缓存、节目单、远程暂停、订阅同步和自动跳片头等功能未作为可用功能展示。

已加入用户指定的 [LibreTV-api-source 列表](https://github.com/ximishan/LibreTV-api-source) 中 17 个苹果 CMS 接口。2026-11-12 首轮搜索检测中 11 个返回结果，6 个连接失败；失败项保留在列表中并默认停用，可以在“片源”页面重新检测并启用。

支持手动增加、修改、删除、检测和停用片源：

- 点播：苹果 CMS 兼容 JSON 采集接口，聚合搜索、线路和选集。
- 直播：HTTP / HTTPS 的 M3U 频道列表。
- 播放：通过服务端代理 HLS / MP4 等媒体，实际格式仍取决于浏览器或 Android WebView 的解码支持。
- 家庭共享：收藏和观看记录由服务端保存，多设备可读取和续播。

“局域网版”指设备访问自家服务端，不代表影片离线。当前预置接口和视频来自互联网，服务端仍需要联网。接口可搜索也不等于每个视频都可播放；上游失效、限速、地域限制、防盗链或编码不兼容会影响播放。

不内置付费内容解锁、网页解析、离线下载、转码、DLNA 投屏、多用户独立资料或外网穿透。自行添加的内容应来自你有权访问的来源。

## 数据、配置与维护

从旧版本更新：将 0.1.4 服务端包解压到新目录，先在旧窗口停止服务，再在新启动器中选择原来的 `data` 文件夹并启动。也可以停止服务后将整个旧 `data` 文件夹复制到新包根目录。不要只移动 EXE 或覆盖一个正在运行的目录。原片源、配对设备和观看记录都来自该数据目录。Android 0.1.2 APK 无需更新。

- Windows 数据在 `data/household.json`；停止服务后备份整个 `data` 文件夹。
- 片源种子只在首次创建数据目录时导入，后续不会覆盖修改或重新加入已删除片源。
- `PORT`：监听端口，默认 `8080`。
- `DATA_DIR`：数据目录；`ADMIN_PASSWORD`：允许局域网管理密码登录。
- `PUBLIC_ORIGIN`：设备实际访问的局域网入口，NAS/Docker 建议必填。
- `ALLOW_PRIVATE_SOURCES=1`：显式允许服务端访问局域网内的媒体接口。默认关闭；仅当你确实需要自建内网片源时开启。

同一数据目录一次只允许一个服务写入，端口被占用时会在打开数据之前停止启动。正常停止会先保存数据并释放目录锁。Linux 可验证旧进程身份失效时会自动恢复遗留锁；无法确认旧进程身份时会拒绝覆盖并给出锁路径。先确认旧服务已停止，再处理锁目录，保留 `household.json`。

播放器、字体与界面脚本随项目提供，界面不依赖远程 CDN。会话保存在本地，配对签名和设备授权由自家服务端处理。已配对设备可以查看家庭共享的观看历史和收藏。

## 开发与检查

```sh
npm test
npm run check
node scripts/probe-sources.mjs
```

片源检测需要联网，会写入 `test-results/source-probe.json`，不会自动修改你的运行数据。打包顺序：

```powershell
.\scripts\build-server-launcher.ps1
.\scripts\package-server.ps1 -NasOfflineBundle .\release\Yingjian-Server-0.1.4-nas1-linux-amd64-Offline
.\scripts\package-nas.ps1
.\scripts\package-player.ps1
```

打包脚本拒绝覆盖现有发行目录；重新打包时用 `-DestinationRoot` 指向新的输出位置。通用发行包不包含实际 `data`、`.env`、启动器设置或日志。NAS 脚本测试为 `node --test deployment/nas/tests/deploy.test.mjs`。

这是为当前需求新建的独立兼容实现，未直接复制 LibreTV 源码；不是 LibreTV 官方发行版。第三方依赖及来源见 `THIRD-PARTY.md`。
