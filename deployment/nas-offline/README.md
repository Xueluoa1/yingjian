# 映间服务端 · NAS 离线镜像包

完整发行包包含 `image.tar`、`image-metadata.txt`、`image.tar.sha256` 和部署配置。NAS 导入镜像后直接启动，不在 NAS 上构建程序，不下载 Node 或 npm 依赖。请按包名和 `image-metadata.txt` 选择 **Linux AMD64 / x86-64** 或 **ARM64 / aarch64**，两者不可混用；不支持 32 位 ARM。需要 Docker 和 Compose v2。

**源码仓库中的本目录只有部署模板。缺少上述镜像文件时，它不是可安装的成品包；实际镜像必须先完成容器运行验证再打包。**

## 飞牛界面安装

1. 将完整发行包上传 NAS 并解压。在 Docker 的镜像页面使用本地导入功能，选择 `image.tar`。AMD64 镜像名为 `yingjian-server:0.1.4-nas1`，ARM64 为 `yingjian-server:0.1.4-nas1-arm64`，应与本包 Compose 一致。
2. 初次安装：将 `.env.example` 复制为 `.env`，填写 NAS 的局域网 IP、端口和管理密码。端口没有占用时可用 `8080`，容器内部端口固定为 `8080`。
3. 创建 Compose 项目，使用本包 `docker-compose.yml` 和同目录 `.env`，启动项目。配置只引用刚导入的完整镜像，不需要点“构建”。
4. 容器状态为健康后，在电脑或手机浏览器访问 `.env` 中的 `PUBLIC_ORIGIN`，例如 `http://192.168.1.8:8080`。管理页提供手机、电视的连接码及二维码。

飞牛不同版本的导入入口名称可能不同；关键是先**导入本地镜像**，再使用 Compose 配置启动。

## 已有项目升级

导入新的 `image.tar` 后，**更新原来的 Compose 项目**，不要再创建第二个同名容器。替换原项目的编排内容为本包 `docker-compose.yml`，保留原 `.env` 中的 IP、端口、管理密码及原数据卷。确认界面保存的编排也已更新，然后重新部署容器，单纯“重启”不会更换镜像。

界面导入无法自动识别旧数据卷。请使用旧容器 `/app/data` 对应的准确卷名填写 `DATA_VOLUME`，并保持原项目名；例如已确认项目为 `yingjian`、卷为 `yingjian-data` 时继续使用它们。原卷若带项目前缀，不要改成另一个默认名字。不要删除原数据卷。

旧 `.env` 里的 `NODE_IMAGE` 可以保留，离线部署会忽略它；本包已固定完整应用镜像，无需再设置 Node 镜像地址。

## 可选：脚本自动导入

在配置好 `.env` 的包目录执行 `sh deploy.sh start`。脚本先校验镜像文件，再导入并启动；已有容器时自动保留原 Compose 项目和实际数据卷。若发现挂载冲突、多个旧数据卷或不支持的架构，会在更新容器前停止。

脚本命令：`validate` 检查配置及镜像元数据；`start` 和 `update` 导入并启动本包镜像；`status` 查看状态；`stop` 停止服务并保留数据。脚本不下载更新、不构建程序，也不会删除数据卷。

## 配置

| 项目 | 内容 |
|---|---|
| `LAN_BIND_IP` | NAS 的局域网 IPv4，例如 `192.168.1.8` |
| `HOST_PORT` | 电脑、手机访问的端口，例如 `8080` |
| `PUBLIC_ORIGIN` | `http://NAS的IP:端口`，必须与上两项一致 |
| `ADMIN_PASSWORD` | 自行设置的 12–128 位管理密码 |
| `DATA_VOLUME` | 初次安装默认 `yingjian-data`；升级使用原卷准确名称 |

密码使用单引号包裹，不能包含单引号、反斜杠或换行。配置文件只交给 NAS 管理者保管。若访问端口已被占用，同时修改 `HOST_PORT` 和 `PUBLIC_ORIGIN`；容器端口无需修改。

离线包解决的是服务部署。在线播放仍取决于片源自身的网络连通情况。
