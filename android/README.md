# 映间 Android 客户端 0.1.2

手机和电视分别安装 `Yingjian-Phone-0.1.2-debug.apk` 与 `Yingjian-TV-0.1.2-debug.apk`。最低 Android 6.0，需要可用且较新的 Android System WebView。APK 不含原生 CPU 专用库，可用于常见 ARM、ARM64 和 x86 安卓设备。

0.1.2 调整了 WebView 播放策略，修复历史续播、换源后停在暂停状态的问题：允许已连接局域网页面在异步加载完成后继续播放。雷电模拟器中已验证手机与电视换源后接续进度并保持播放。更新沿用原调试签名，已验证直接覆盖安装 0.1.1 并保留连接信息。

## 安装与连接

1. 先在电脑或 NAS 启动映间服务端，手机、电视连接同一路由器。
2. 将对应 APK 复制到设备并安装，按系统提示允许当前文件管理器安装应用。
3. 电脑管理页打开“连接设备”，选择实际局域网地址后生成配对信息。
4. 手机可选择“扫描二维码连接”，也可粘贴完整配对链接。手动连接时，在同一页面填写“服务端地址”和“6 位连接码”后连接。
5. 电视在连接页输入地址（例如 `192.168.2.20:8080`，可省略 `http://`）和服务端生成的六位连接码，然后选择“连接服务端”。输入码时弹出数字键盘；使用遥控器方向键、确认键、返回键操作。电视不申请相机权限。

链接示例：`http://192.168.2.20:8080`。这个地址只适用于当前服务端 IP；其他电脑请使用其管理页显示的地址。设备必须能访问服务端的 TCP 8080 端口。

二维码在手机本地识别，不上传相机画面。只接受私有 IP 或解析到私有 IP 的 `.local` / `.lan` 主机名。二维码与六位配对码由服务端生成，一次使用，十分钟有效。连接码不会保存到设备；连接成功后记住地址，已配对会话由系统 WebView 保存，下次打开自动连接，无需重新输入连接码。完整配对链接不需要额外输入连接码。上方“连接设置”可以更换服务端。

## 试用范围

这是可侧载的调试签名试用包，尚未上架应用商店。客户端采用原生连接与扫码界面加 WebView 播放页面，界面与片源由局域网服务端提供。电视版具有 Android TV 启动入口，也可从普通安卓盒子的应用列表启动。系统解码器和 WebView 决定实际视频格式支持，不含转码、下载或后台播放服务。

已完成 0.1.2 手机/电视 APK 离线构建、签名、权限、版本和启动入口检查；38 项地址、端口、同源和连接码校验及离线 QR 编解码测试通过。新旧 APK 签名一致。

雷电 14（Android 14 / WebView 146）已完成两个 0.1.2 APK 的覆盖安装和动态复测：手机从历史位置自动播放，打开播放设置不中断播放，切换片源后保持集数和进度并继续播放；电视使用无协议的地址加六位连接码连接，方向键与确认键可完成连接和首页选片，重启自动连接，播放区域可以通过方向键进入和离开，全屏与返回、选集和关闭详情均正常，换源后继续播放。电视页面同时适配了模拟器约 1097 CSS 像素的可用宽度，首页分类及推荐区可在首屏完整显示。详细记录和截图见 `release/android/ldplayer-validation-0.1.2.json`。

2026-11-15 在雷电 14.0.32.1（Android 14 / WebView 146.0.7680.119）补测了手机完整配对链接：通过原生“更换服务端”表单粘贴 `/connect#pair=...` 链接，连接码留空，在网页确认后成功新增手机设备；强制停止并重开后自动进入首页。本次是在已有会话上重新配对，并非清空 Cookie 后的全新环境。测试后已恢复模拟器原始 1920 × 1080 分辨率，密度保持 280。

ApkStart 补测因其 Android 运行环境反复自行退出而阻塞，未完成 APK 安装及运行，不能视为兼容性通过或 APK 故障；独立记录见 `release/android/apkstart-validation-0.1.2.json`。模拟器验证不能替代物理设备测试，摄像头扫码、实体电视遥控器与软键盘、硬件解码及 NAS 部署仍需在对应设备验证。

## 从源码构建（Windows）

准备 JDK 17、Android SDK Platform 35、Android SDK Build Tools 35.0.0。接受 SDK 许可后执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\build-local.ps1 -JdkPath 'C:\Tools\jdk-17' -SdkPath 'C:\Android\Sdk'
```

Gradle Wrapper 使用 Gradle 8.9。首次构建需要联网下载 Gradle 和 Android Gradle Plugin。已有 Gradle 安装可增加 `-GradlePath 'C:\Tools\gradle-8.9'`；依赖完整缓存后可以增加 `-Offline`。

脚本仅在工程目录创建 `.signing/debug.keystore`、`.gradle-home` 和 `.android-user`，不会更改 JDK/SDK。调试密钥不随源码打包；请保留自己的密钥以便后续覆盖安装。不同密钥的 APK 需要先卸载旧应用再安装，卸载会清空该客户端保存的连接信息。

输出：

- `app/build/outputs/apk/phone/debug/app-phone-debug.apk`
- `app/build/outputs/apk/tv/debug/app-tv-debug.apk`

源码依赖、许可证见 `THIRD-PARTY.md`。
